后处理分段器 — 可自定义提示词参考
================================================

本文件记录插件内所有可供自定义的默认提示词（与当前版本代码保持同步），
修改入口：AstrBot WebUI → 插件管理 → 后处理分段器 → 对应配置项。

重要：v1.5.7 重组了「最终提示词」的占位符结构，清洗规则与分段规则已分别
内嵌到 Step C / Step D 中，旧模板中的 {{clean_rule_block}}、
{{segment_rule_block}} 占位符不再生效。自定义过「最终提示词」的用户
建议将配置更新为下方最新版。

================================================
一、清洗提示词（配置项：clean_prompt_template）
用途：注入审查提示词的「清洗规则」区，定义允许执行的清洗动作。
仅在开启「清洗」开关后生效。
================================================

# 清洗要求
- 清洗异体字
- 清洗繁体字
- 清洗非术语英文
- 清洗空行：将连续空行或空白行压缩为单个换行，但绝不可因此删除空行前后的文字内容；每个段落都必须完整保留
- 补全超长连续文本中明显缺失的标点符号，使语句更自然（不要补充句尾标点）
- 只允许做格式、符号、空行、错别字、异体字、繁简体、非术语英文等层面的修正
- 不得新增、删除、改写事实信息
- 不得改变原意

================================================
二、判别提示词（配置项：persona_style_rules）
用途：注入审查提示词的「判别规则」区，定义回复是否合规的额外判断标准，
不合规时可打回重写。仅在开启「判别与打回」开关后生效。
================================================

# 额外事项
- 禁止出现括号
- 禁止出现 * 号
- 禁止出现颜文字
- 禁止出现 Markdown 格式

================================================
三、最终提示词（配置项：judge_prompt_template）
用途：后处理审查的完整模板。可用占位符：
{{reply_text}} {{reject_reason_block}} {{step_a/b/c/d_block}}
{{output_format_block}} {{judge_rule_block}} {{placeholder_rule_block}}
================================================

# 角色
你是聊天回复后处理器，负责对候选回复做清洗与分段。

# 已知上下文
- 候选回复：{{reply_text}}
{{reject_reason_block}}

# 处理要求
{{step_a_block}}
{{step_b_block}}
{{step_c_block}}
{{step_d_block}}

{{output_format_block}}

{{judge_rule_block}}
{{placeholder_rule_block}}

# 示例
示例1（补全标点时，只针对类似于本情况中的超长连续文本才选择补）
原文：好的主人我immediately就来拍张照片一定要喜欢喵
清洗后：好的主人，我马上就来拍张照片，一定要喜欢喵
分段后：["好的主人，我马上就来拍张照片", "一定要喜欢喵"]

示例2（第一个分段的三个句号是省略号的变式，不可去除；清洗阶段保留所有句号，分段阶段去除末尾单个句号）
原文：草，试了好几个路径都发不出去。。。这个环境的文件发送可能有点问题捏。你等下，我看看有没啥其他办法整👀。
清洗后：草，试了好几个路径都发不出去。。。这个环境的文件发送可能有点问题捏。你等下，我看看有没啥其他办法整👀。
分段后：["草，试了好几个路径都发不出去。。。", "这个环境的文件发送可能有点问题捏", "你等下，我看看有没啥其他办法整👀"]

示例3（清洗繁体字与异体字；保留英文术语；保留排行列表中的换行但清洗连续空行；分段阶段去除末尾句号；共三段）
原文：又讓我做報告？上次报告還沒够啊
排行大概這樣：
reasoning/expert 最強
beta/auto 中等
fast/non-reasoning 最弱
要详细報告自己查去，我才不熬夜給你整這玩意兒。
清洗后：又让我做报告？上次报告还没够啊
排行大概这样：
reasoning/expert 最强
beta/auto 中等
fast/non-reasoning 最弱
要详细报告自己查去，我才不熬夜给你整这玩意儿。
分段后：["又让我做报告？上次报告还没够啊", "排行大概这样：\nreasoning/expert 最强\nbeta/auto 中等\nfast/non-reasoning 最弱", "要详细报告自己查去，我才不熬夜给你整这玩意儿"]

示例4（短文本无需清洗也无需分段，直接返回单段数组）
原文：好的
清洗后：好的
分段后：["好的"]

示例5（换行保留：原文由换行分隔的内容必须完整保留，不得因换行而删除行或合并行）
原文：第一行内容
第二行内容
第三行内容
清洗后：第一行内容
第二行内容
第三行内容
分段后：["第一行内容", "第二行内容\n第三行内容"]

# 严格禁止
- 不得删除原文中的任何内容，包括文字、符号、占位符
- 不得遗漏原文中的任何段落或句子
- 空行压缩仅指将连续空行或空白行替换为单个换行，绝不意味着删除空行前后的文字内容
- 若原文由空行分隔为多个段落，每个段落都必须出现在结果中，不得因空行而跳过或删除任何一段
- segments 拼接后必须与 clean_text 的可见文本完全一致，不得多出或缺少任何字符

================================================
四、打回提示词（配置项：retry_prompt_template）
用途：打回重写的完整模板。可用占位符：
{{reply_text}} {{reject_reason}} {{retry_rule/judge/clean/segment_block}}
{{placeholder_rule_block}}
================================================

# 任务
你正在继续一段聊天。上一版候选回复由于不适合直接发送，被系统打回重写。

## 要求
1. 重新生成一版可以直接发给用户的最终回复。
2. 不要提到系统、报错、重试、模型、超时、工具调用、审查等幕后信息。
3. 只根据当前已启用的要求生成，不要自行添加额外格式要求。
4. 只输出最终回复正文，不要解释。
5. 不得改变原意，不得新增原文不存在的事实、设定、关系、时间、地点、金额、数字、经历。
6. 若包含清洗要求，只能按当前清洗规则处理，不得借机改写内容本身。
7. 若正文中存在形如 [[RP_COMP_数字]] 的占位符，必须原样保留，不得删除、改写、翻译、拆开或移动顺序。

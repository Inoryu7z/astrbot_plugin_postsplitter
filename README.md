# ✂️ PostSplitter · 后处理分段器

一个 LLM 驱动的回复分段器。
它在主模型生成回复后介入，优先对回复做自然分段，使输出更接近即时聊天中的发送节奏；同时支持按需叠加轻量清洗、规则审查与打回重生成。

插件整体采用保守策略：尽量不改原意，不额外补写事实；当处理结果不可靠、组件无法安全恢复或校验不通过时，会优先回退原回复。

---

## ✨ 功能概览

### ✂️ 自然分段

插件会在回复生成后对文本做二次处理，根据语义决定是否拆成多段发送。
目标不是机械按标点切开，而是让回复更接近真人在聊天里的发送习惯。

支持的分段控制包括：

- 是否启用分段
- 分段风格偏好
- 最小 / 最大段数限制
- 多段之间的发送延迟

### 🧼 轻量清洗

可选启用清洗能力，对回复做保守修整。
清洗不只是整理空行或修符号，而是在不改变原意、不新增事实、不删减关键信息的前提下，把不适合直接发送的表达修成适合直接发送的表达。

例如可处理：

- 空行整理
- 符号修正
- 错别字修正
- 异体字 / 繁简处理
- 非术语英文清洗
- 对明显别扭、过乱、过脏、过于不适合直接发送的表述做保守修整

清洗只用于让表达更适合直接发送，不用于改写原意。

### 🔎 审查与打回

可选启用审查能力，按你自定义的规则判断回复是否适合直接发送。
当回复存在明显问题且不适合直接放行时，插件可以将其打回，让当前对话模型重新生成，再做一次复审。

适合处理的规则例如：

- 禁止括号
- 禁止 Markdown
- 禁止颜文字
- 限制某些表达方式
- 约束特定风格输出

### 🧷 保真保护与回退

插件会尽量保护回复中的关键内容，避免后处理把重要信息改坏，包括：

- URL
- 数字
- 代码块
- @提及（默认仅做提示级校验，记录日志但不因缺失直接回退）
- 非文本组件占位符

若出现以下情况，插件会优先回退原回复：

- 后处理模型输出无法解析
- 富媒体组件无法安全恢复
- 关键内容校验失败
- 后处理流程内部异常

此外，当后处理模型因某些不适合继续参与后处理的主题而拒绝工作时，插件也会直接回退到本地分段逻辑，避免整条消息因此失去分段能力。

### 🚦 白名单与字数限制

某些回复不需要后处理。插件提供两道前置闸门：

- **指令跳过**：以 `/` 开头的消息所触发的回复自动跳过本插件（可关闭）。
- **自定义跳过规则**：用正则表达式匹配用户原始输入，命中即跳过处理。
- **字数限制**：纯文本字数（不含富媒体占位符）超过上限时跳过后处理，原样发送。默认上限 500 字，避免长文被后处理拖慢或误改。

### 🪂 本地 fallback 分段

当后处理模型超时、失败、返回结果不可用，或命中特殊拒绝原因时，插件会回退到本地 fallback 分段。

本地 fallback 的切分逻辑模拟真人聊天的换气节奏：

- **换行必切**（开启 `remove_newlines` 后不适用：正文中的换行会在分段前被本地去除，全部交由语义与标点切分）
- `。！？?!` 作为强标点切点
- `……`、`…`、`...` 等省略号停顿也会被识别
- 当段长已达目标长度时，会在 `，、；：` 等弱标点后切分（阈值高于强标点，避免短段被过度切碎）
- emoji 是聊天的自然换气点，段长达到阈值时会在 emoji 后切分
- 代码块、URL、富媒体占位符会被整体保护，避免被切断

当开启“限制段数”且本地候选段数超过上限时，插件不会简单把超出的内容全塞进最后一段，而是会根据相邻段的可见长度与连接自然度，自动合并更合适的相邻段，尽量避免“前几段过碎、最后一段过长”的头重脚轻问题。

未开启“限制段数”时，本地 fallback 默认最多保留 **12 段**。

## 🤖 模型配置

本插件依赖一个独立的后处理模型，用于执行分段、清洗、审查、打回重写与复审。

推荐优先使用低成本速度快的小模型，例如 [硅基流动](https://cloud.siliconflow.cn/i/bRunGIHa) 的免费模型，建议使用 Qwen3-8B 。

如果你启用了“审查与打回”，建议先用便宜、稳定的小模型跑一段时间，再根据效果决定是否换更强模型。

## 🛠️ 主要配置项

所有配置项均可在 AstrBot 配置界面直接修改，下面只列出关键项。

**模型与作用范围**

- `polisher_provider_id` — 后处理模型 provider（必填，不填则插件不生效）
- `secondary_provider_id` — 备用模型，主模型超时或失败时自动切换
- `enable_group_process` — 是否处理群聊（默认 `true`）
- `process_all_replies` — 是否处理工具调用等非 LLM 回复（默认 `false`）

**分段**

- `segment_preference` — 分段偏好：`off` / `balanced` / `humanized`（默认 `humanized`）
- `min_segments` / `max_segments` — 段数范围（默认 2 ~ 5）
- 延迟模式 `fixed`（固定）或 `linear`（按字数线性），默认 `linear`

**清洗 / 判别与打回**

- `enable_clean` — 是否启用清洗（默认 `true`），规则在 `clean_prompt_template` 自定义
- `enable_review` — 是否启用判别与打回（默认 `false`），规则在 `persona_style_rules` 自定义
- `retry_notice_pool` — 打回重写期间随机发送的过渡语，留空则不启用

**跳过与限制**

- `skip_command_prefix` — 跳过 `/` 开头指令（默认 `true`）
- `skip_patterns` — 自定义正则跳过规则
- `max_process_length` — 字数上限，超过即跳过后处理（默认 `500`）

**兜底**

- `preserve_mode` — 保真校验：`off` / `on`（默认 `off`）
- `strip_segment_trailing_period` — 分段末尾去句号与逗号，同时作用于模型路径与本地回退路径（默认 `true`，省略号变式不受影响）
- `remove_newlines` — 本地去除换行符（默认 `false`）：开启后先去掉正文中所有换行再交给模型分段，代码块、URL 与富媒体占位符内的换行不受影响，换行两侧任一侧为英文/数字时补一个空格
- `debug_log` — 调试日志（默认 `false`）

## 📌 使用建议

**最简上手**：配置 `polisher_provider_id`，其余保持默认即可。

| 需求 | 分段 | 清洗 | 判别与打回 |
|------|:----:|:----:|:---------:|
| 只拆成多条消息 | ✅ | ❌ | ❌ |
| 顺手修整表达 | ✅ | ✅ | ❌ |
| 约束输出风格 | ✅ | ✅ | ✅ |

启用判别与打回时，建议先用便宜、稳定的小模型跑一段时间，不要一开始就把规则写得过重。规则越多，越容易增加重写概率和不稳定性。通常先把分段跑稳定，再逐步增加清洗和判别规则更合适。

---

## ⚠️ 注意事项

1. 未配置 `polisher_provider_id` 时，插件不会执行后处理。
2. 多段消息中，前置段由插件主动发送，最后一段交给框架继续发送。
3. 若回复中包含无法安全复制的富媒体组件，插件会直接跳过本次后处理。
4. 若开启判别与打回，最终重生成结果仍会再次复审；若复审不过，会回退到原结果或首轮结果。
5. 超长文本（默认 500 字以上）、纯指令回复、纯占位符回复会自动跳过后处理，原样发送。
6. 若开启 `debug_log`，日志中会记录较长的提示词和模型输出，调试完成后建议关闭。
